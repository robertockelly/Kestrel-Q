## 4. Verified configuration facts

The following are direct high-confidence facts from pinned `config.json`, the
pinned model card and the official checkpoint index.

### Top-level model

- repository/model ID: `Qwen/Qwen3.8-Flash-Next`;
- model type: `qwen4_exp`;
- declared architecture: `Qwen4ExpForConditionalGeneration`;
- `language_model_only`: `false`;
- released model is a multimodal wrapper with text and vision configuration;
- canonical text configuration dtype: `bfloat16`;
- tied word embeddings: `false`.

### Text configuration

- text model type: `qwen4_exp_text`;
- vocabulary size: **248,320**;
- hidden size: **2,560**;
- text layers: **48**;
- layer pattern: **12 repetitions** of three `linear_attention` layers followed
  by one `full_attention` layer;
- `full_attention_interval`: **4**;
- configured native maximum positions: **262,144**;
- attention heads: **24**, key/value heads: **2**, head dimension: **256**;
- linear-attention key heads: **16**, value heads: **48**, key/value head
  dimensions: **128**;
- Gated Residual configuration: `hc_count = 4`, `hc_lowrank = 320`;
- official model card describes approximately **125B** main parameters,
  **51B** N-gram-embedding parameters, **4B** MTP parameters and **6B** active
  parameters per token. These are upstream model-card figures, not a Task 1.2
  tensor-footprint derivation.

### MoE configuration

- routed experts selected per token: **10**;
- routed expert intermediate size: **640**;
- shared expert intermediate size: **640**;
- the official model card identifies **one shared expert** in addition to the

## 7. Metadata-tool development findings

Three local PowerShell issues appeared before the canonical manifest completed:

1. An interpolated variable immediately followed by `:` was parsed as a scoped
   variable. Braced interpolation fixed the parse failure; it occurred before
   any network request.
2. Hugging Face ordinary Git-blob records omit the optional `lfs` property.
   `Set-StrictMode` correctly rejected direct access, so the tool now tests for
   property presence before reading LFS metadata. Only the first allowlisted
   non-weight file had been cached at that point.
3. Ordered dictionaries did not expose `size_bytes` to `Measure-Object` as an
   object property. Manifest file entries now use `PSCustomObject`, allowing the
   aggregate shard-size assertion to complete.

Regression evidence after the fixes:

- PowerShell parser error count: zero;
- canonical capture: 144 files listed, 13 metadata files downloaded, zero
  weight shards downloaded;
- byte-for-byte repeated manifest: PASS;
- downloaded size/SHA-256 revalidation: PASS;
- non-40-hex revision rejected before output creation: PASS.
